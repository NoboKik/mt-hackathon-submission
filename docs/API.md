# API для интеграции: HR и LMS

Полная спецификация — OpenAPI 3.1 в [`apps/web/public/openapi.yaml`](../apps/web/public/openapi.yaml).
На развёрнутом сервере она же открывается интерактивно: **`https://<домен>/api-docs.html`**
(Swagger UI, можно отправлять запросы прямо со страницы).

Игровые маршруты (`/api/me`, `/api/sessions/…`) рассчитаны на браузер и cookie сессии. Внешней
системе нужны два маршрута: HR-система заводит сотрудников (`PUT /api/integration/users/…`) и
забирает их прогресс (`GET /api/integration/progress`).

## Включение

Интеграция выключена, пока на сервере не задан токен. В `infra/.env`:

```bash
INTEGRATION_TOKEN=<openssl rand -hex 32>
```

и перезапуск: `docker compose -f infra/docker-compose.yml up -d web`. Без токена маршрут
отвечает `404 {"error":"integrationOff"}` — на чистой установке наружу ничего не открыто.

## Регистрация сотрудников

Проводники не регистрируются сами — их заводит HR-система, по табельному номеру:

```bash
curl -X PUT -H "Authorization: Bearer $INTEGRATION_TOKEN" -H "Content-Type: application/json" \
  https://<домен>/api/integration/users/004512 \
  -d '{"email":"a.smirnova@vsm400.ru","name":"Анна Смирнова","depot":"Депо Москва-Октябрьская",
       "crew":"Бригада № 3","position":"Проводник","password":"Vsm-400-start"}'
```

| Поле | Смысл |
| --- | --- |
| `email` | Логин для входа |
| `name`, `depot` | Имя и фамилия, депо — обязательны |
| `crew`, `position` | Бригада (`""` — не назначена) и должность (по умолчанию «Проводник»). «Начальник поезда» и «Методист» открывают аналитику бригад |
| `password` | Начальный пароль, от 8 символов. Обязателен при создании; при обновлении — только чтобы сменить |

| Ответ | Когда |
| --- | --- |
| `201 {"id":…,"employeeId":"004512","created":true}` | Сотрудник создан |
| `200 {…,"created":false}` | Обновлён. Повторный вызов с теми же данными ничего не меняет |
| `400 {"error":"badRequest"}` | Невалидное тело или табельный номер (латиница, цифры, `_.-`, до 64 символов) |
| `400 {"error":"passwordRequired"}` | Новый сотрудник без пароля |
| `409 {"error":"emailTaken"}` | Email уже у другого сотрудника |
| `401`, `404` | Как у выгрузки ниже |

Учётная запись, созданная раньше через `pnpm user:add` с тем же email, не дублируется — к ней
привязывается табельный номер. `id` в ответе — тот же, что в выгрузке прогресса.

## Выгрузка прогресса

```bash
curl -H "Authorization: Bearer $INTEGRATION_TOKEN" https://<домен>/api/integration/progress
```

| Ответ | Когда |
| --- | --- |
| `200` | Выгрузка |
| `401 {"error":"unauthorized"}` | Нет заголовка `Authorization` или токен неверный |
| `404 {"error":"integrationOff"}` | На сервере не задан `INTEGRATION_TOKEN` |

Токен сравнивается за постоянное время. Передавайте его только по HTTPS (Caddy выдаёт
сертификат сам) и храните в секретах системы-потребителя, не в коде.

## Что приходит

```json
{
  "generatedAt": "2026-09-25T12:00:00.000Z",
  "employees": [
    {
      "id": "5a2b9e4c-0f1d-4c3b-8e7a-6d5f4c3b2a19",
      "name": "Анна Смирнова",
      "depot": "Депо Москва-Октябрьская",
      "crew": "Бригада № 3",
      "xp": 420,
      "rank": "conductor",
      "competencies": { "conflict": 6, "medical": 0, "safety": 4, "service": 2, "communication": 7 },
      "badges": ["first-run", "diplomat"],
      "runs": 4,
      "lastRunAt": "2026-09-24T09:12:03.000Z",
      "readiness": {
        "ready": false,
        "percent": 88,
        "criteria": [
          { "key": "service", "value": 2, "target": 4, "met": false },
          { "key": "conflict", "value": 6, "target": 2, "met": true },
          { "key": "communication", "value": 7, "target": 2, "met": true },
          { "key": "serviceBest", "value": 107, "target": 100, "met": true }
        ]
      }
    }
  ]
}
```

| Поле | Смысл |
| --- | --- |
| `id` | Внутренний идентификатор сотрудника в тренажёре. Не меняется; сопоставляется с табельным номером в HR-системе один раз |
| `name`, `depot`, `crew` | ФИО, депо, бригада (`""` — не назначена) |
| `xp` | Сумма лучших результатов по сценариям — повторное прохождение повышает её, но не суммируется |
| `rank` | `trainee` / `conductor` / `senior` / `mentor` — Стажёр / Проводник / Старший / Наставник |
| `competencies` | Баллы по пяти компетенциям: урегулирование конфликтов, медицинская помощь, безопасность и регламент, премиальный сервис, коммуникация |
| `badges` | Коды полученных достижений, в порядке получения |
| `runs`, `lastRunAt` | Число завершённых прохождений и дата последнего |
| `readiness` | Готовность к бизнес/первому классу: пороги по премиальному сервису, конфликтам и коммуникации плюс лучший результат в сервисном сценарии (успех — от 100). `ready` — все критерии выполнены, `percent` — средний прогресс по ним |

**Чего в выгрузке нет:** email, пароли, IP, подробные пути по сценариям. Это минимальный набор
для учёта обучения (принцип минимизации, 152-ФЗ).

## Типовые сценарии

- **LMS:** раз в сутки забирать выгрузку и отмечать в карточке сотрудника уровень и баллы
  компетенций; `lastRunAt` старше N дней — повод назначить тренировку.
- **HR:** `readiness.ready` — кандидаты на перевод из стандарта/комфорта в бизнес/первый класс.
  Слабая компетенция по бригаде — тема для наставника. Для разбора по узлам сценариев есть
  экран «Аналитика» (`/admin/analytics`) и маршрут `GET /api/admin/analytics`; они открыты
  начальникам поездов и методистам (должность в `position`), остальным — `403 {"error":"analyticsForbidden"}`.

Выгрузка для биллинга и push-вебхуки в LMS — в плане развития (см. README).
